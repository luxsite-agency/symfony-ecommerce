# Вхід покупців через Google

Рішення власника 13.10.2026: «авторизація в кабінеті спільна» — Google лише ще один спосіб входу в той самий кабінет
покупця (замовлення, адреси, обране, відгуки), не окремий акаунт. Один `Customer` — пароль, посилання з листа і Google
як способи входу. Технічні рішення — `docs-adr.md`, розділ «Вхід через Google».

## Що треба зробити власнику магазину (разово, 15 хвилин)

Усе робиться в адмінці: **Налаштування магазину → розділ «Вхід через Google»** під списком (лише ROLE_ADMIN). Там уже
готові адреси для Google Cloud Console з кнопками «Копіювати», та сама покрокова інструкція трьома мовами й кнопка
«Перевірити налаштування».

1. **Google Cloud Console** → https://console.cloud.google.com/ → проєкт магазину (або новий: «New project»,
   назва = домен магазину).
2. **APIs & Services → OAuth consent screen** («Google Auth Platform → Branding/Audience» у новому інтерфейсі):
   - User type: **External**. Publishing status: **In production** (у статусі Testing входять лише 100 тестових
     адрес, і екран згоди показує попередження).
   - App name — назва магазину, support email і developer contact — пошта магазину, логотип — за бажанням
     (з логотипом Google вимагає верифікацію бренду; без логотипа — не вимагає).
   - **Authorized domains**: домен магазину (`example.com`, без `www`, без шляхів).
   - Посилання на політику конфіденційності й умови — сторінки магазину (обов'язкові для production).
   - **Scopes**: лише `openid`, `email`, `profile` (не sensitive — без перевірки Google).
3. **APIs & Services → Credentials → Create credentials → OAuth client ID**:
   - Application type: **Web application**, name — домен магазину.
   - **Authorized JavaScript origins**: значення «Authorized JavaScript origin» з адмінки (`https://<site_host>`; і з
     `www.`, якщо магазин відкривається з www).
   - **Authorized redirect URIs**: значення «Authorized redirect URI» з адмінки (`https://<site_host>/account/google/callback`;
     і з `www.`, якщо є). Точний збіг, без слеша в кінці, лише https. Мовні префікси не потрібні: рушій завжди
     підставляє адресу без префікса.
   - Скопіювати **Client ID** (`…apps.googleusercontent.com`) і **Client secret**.
4. **В адмінці**, група «Вхід через Google» у списку налаштувань: вставити Client ID у «Client ID», Client Secret у
   «Client Secret» (зберігається шифровано ключем `SETTINGS_SECRET_KEY`, як ключ OpenRouter — `docs/ai.md`; показується
   лише маскою `…a1b2`; порожнє поле при збереженні — лишити чинний), увімкнути «Увімкнено». Зміни діють одразу.
5. **Перевірити налаштування** (кнопка в розділі): формат Client ID, стан секрету, перемикач, доступність discovery і
   JWKS Google із сервера. Повний вхід — «Спробувати на сайті» (сторінка входу в новій вкладці) → «Продовжити з Google»
   своїм акаунтом; у `var/log/security_audit.log` з'являються `customer.google_started` і `customer.login` з `via: google`.

Ротація секрету: створити новий secret у тому ж OAuth-клієнті (Credentials → клієнт → «Add secret»), вставити в
адмінці, потім вимкнути старий у Cloud Console. Client ID не змінюється, покупців не чіпає.

### Пріоритет і fallback для стендів

- Перемикач «Увімкнено» + Client ID правильного формату + Client Secret, що розшифровується → працюють ключі з адмінки.
- Перемикач увімкнено, а ключі неповні (нема Client ID, формат не той, секрет не задано, нема `SETTINGS_SECRET_KEY`,
  секрет не розшифрувати після зміни ключа) → вхід **вимкнений**, розділ в адмінці каже чому; на env не відкочуємось.
- Перемикач вимкнено → fallback на змінні `GOOGLE_OAUTH_CLIENT_ID` / `GOOGLE_OAUTH_CLIENT_SECRET` з `.env.local` (стенди
  агенції; у магазину клієнта їх нема). Розділ показує «працюють ключі зі змінних сервера».
- Нічого з цього → кнопки «Продовжити з Google» нема ніде, адреси `/account/google/*` відповідають 404.

Секрет: у БД лише конверт SecretBox (дамп містить конверт, не значення); `Settings::get()` віддає маску, тож шаблони,
Admin API і MCP значення не бачать; у `security_audit` — `settings.secret_set` з маскою і `settings.changed` для
Client ID та перемикача (код, хто, коли; без значень).

## Як це працює для покупця

- Кнопка на сторінках входу й реєстрації (одна дія: нового покупця створює, наявного впускає) і в модальному
  «увійдіть, щоб залишити відгук» (епік відгуків). Повертає на сторінку, з якої прийшов (лише відносні адреси сайту).
- Новий покупець: кабінет з підтвердженим email без пароля. Пароль за бажанням — «забули пароль» на свою адресу
  (у профілі посилання «встановіть пароль»).
- Наявний покупець з тією ж адресою (підтвердженою в Google) — Google прив'язується автоматично, пароль лишається.
- У профілі: «Google підключено: <адреса акаунта Google>, з <дата>» + «Відключити» (лише коли є пароль) або «Підключити
  Google» (питає поточний пароль). Адреса в Google може відрізнятись від адреси кабінету — тому її і показуємо.
- Про кожне підключення (автоматичне при вході чи з кабінету) і відключення покупцю йде лист на адресу кабінету з адресою
  акаунта Google і порадою «якщо це були не ви — відключіть у профілі й змініть пароль». Лист про зміну пароля (зокрема
  після «забули пароль») теж називає підключений Google: скинутий пароль не відключає Google-вхід.
- Покупець лише з Google (без пароля) не може змінити адресу, завантажити експорт даних чи видалити акаунт — ці дії
  потребують поточного пароля. Замість форми такі сторінки показують «спершу встановіть пароль» з посиланням на «забули
  пароль» на свою адресу; після цього все доступно.
- Демо-акаунти й адреси адміністраторів через Google не входять.
- Вхід через Google не ставить cookie «запам'ятати мене»: сесія живе як звичайна; наступного разу — знову кнопка (один клік).
- Відгуки (`docs/reviews.md`): кнопка «Увійти через Google, щоб залишити відгук» веде на цей самий вхід; покупцю без
  прив'язки при `app.reviews.require_google` — на сторінку підключення Google у профілі.

## Що бачить власник у журналі (`security_audit`)

`google_started`, `google_signup` (новий), `google_linked` (прив'язка за адресою або з кабінету), `google_placeholder_verified`
(неперевірена реєстрація стала акаунтом через Google), `google_unlinked`, `google_failed` (reason: state, cancelled,
id_token_*, token_*, email_unverified, demo, admin, disabled, already_linked; код `?error=` від Google — лише зі стандартного
переліку, інше — `other`), `google_ignored` (callback входу в уже залогіненій сесії), `google_link_failed`, `google_rate_limited`;
`mail_google_linked` / `mail_google_unlinked` — листи;
сам вхід — `login` з `via: google`. Адреси в журналі — HMAC, IP — анонімізовані, як для всіх подій кабінету.
